# 跨仓委托协议 v1 —— 修改本项目目录树之外的文件时的标准路径

语汇遵循 RFC 2119。本协议约束**委托方**（在 cwd 项目内工作的会话）与**受托子会话**（agora_dispatch 拉起的一次性会话）；完整工作流背景读 `wiki/topics/delegation.md` 或本文件。

## 一、适用

- 修改 cwd 项目目录树之外的文件即**跨仓**（MUST 委托，MUST NOT 直接用文件工具改他仓）。
- Trivial 豁免（≤1 文件 ≤20 行）仅限当前项目，**不适用于跨仓**——跨仓一律委托。

## 二、流程

1. **名册**：目标仓无实体页则 `agora_wiki_write` 建 `wiki/entities/<名>.md`（一次性；`dirs:` 指向目标仓路径）。
2. **项目页**（可选）：`wiki/projects/<名>.md` 注册 path/verify。
3. **建任务**：`agora_task_create`——`title`/`project_dir`/`verify` 必填；**verify 即验收合同**（机械层在 project_dir 真实执行，done 的唯一机械门）。
4. **派发**：`agora_dispatch(project, task, prompt)`。
5. **等待**：委托方 MAY 结束回合，由通知桥或下次开场唤醒；或盯任务唤醒集（done/blocked/cancelled），`TASK=<id> bash ~/plaza/scripts/history.sh` 轮询。
6. **审计**：`agora_history(task)` 事件链 + 证据（`ref` 定位）。

## 三、与宿主准则的关系（优先级声明）

- **协作域**（账本/委托/广场写路径/开场仪式）：以 agora 随附说明为准（本文件、docs/AGENTS.md、接口规格）。
- **工程域**（编码/调试/评审纪律）：以宿主全局 AGENTS.md 为准。
- verify 门是**机械验收**，**不豁免**目标仓自身评审流程（含宿主的完成评审纪律）。

## 四、worktree×verify 执行约定

- 子会话 MUST 遵守宿主 worktree 铁律（独立 worktree、线性历史、用毕清理）。
- **合并回主分支后**再 `done`——verify 门在 project_dir 对合并后状态执行；在 worktree 内 done 则 verify 测的是未合并代码，判 FAIL。
- Trivial 豁免内（仅当前项目）可直接改，不适用本节。

## 五、权限决策

- 子会话以 `--auto` 运行 = 自动放行未显式 deny 的权限；依据接口规格 §6 Non-Goals（单机信任模型）接受。
- 最小 denylist（`opencode run*`/`serve*`/`sudo*`/`git push*`/`rm -rf /*`，经 OPENCODE_CONFIG_CONTENT 注入）记录为后续加固项，本次不实施。

## 六、sessions.map 约定与限制

- 登记格式：`<host> <agent> <session> <ts>`；通知桥为写入者。
- 无通知桥时，在场优先退化为「总是 spawn」——已知限制；机械写入者（拉起模板自登记）留作后续。

## 七、遗留残留

- `.omo/cross-repo/`、目标仓 `.review-loop/` 登记、`~/.local/state/cross-repo/admission`——惰性残留，可手清。

## v2 增补 —— 全量委托（2026-10-23，设计 v1.2.1 L1）

- **一律委托**：本机任意 git 仓的代码改动一律经 agora 委托执行（Trivial 豁免取消；闸＝宿主 dotfiles 插件，agora 上游保持无插件；会话唯一可写位置＝凭据核验通过的委托树）。
- **合并职责上移**：子会话不合并、done 即止（wt 树上 commit＋自验，verify 在 `wt_dir`）；合并由 dispatcher 经 `merge.sh` 闭环——ff-only、集成 verify 在合并目标真跑、`merged` 事件＋清树；FAIL 原子回滚＋blocked→reopened 返工。
- **合并目标二分**：同仓链（上游 dispatcher 任务主仓==本任务主仓）→上游 wt 分支；跨仓/无上游→目标仓默认分支。
- **链式 (ii) 恢复性重派**：b 派 c 后 post progress 即退出；c done 超 `AGORA_MERGE_WAIT_MIN` 未合并 → poll 对上游落 diagnosed 并恢复性重派（续跑 BOOT：history 自查→评审 diff→merge.sh）；重派上限 `AGORA_REDISPATCH_MAX` 超限 escalated @operator。
- **注入式续跑与 ack 注入（2026-10-23 L2，接口规格 v1.33）**：上游会话经 API 通道派生（dispatched 带 `session:`）时，poll 的恢复性重派**优先注入续跑 prompt 进既有会话**（保上下文、零新会话；wt_host≠本机不注入——sid 只在本机 opencode 服务有效），失败/无 session 回落 spawn 重派；dispatcher 的 `ack` 在任务带 `session:` 时由 post.sh 直接 inject「ack 已落账，继续」（幂等凭据，best-effort）——plan-ack 死锁窗闭合，子会话零中程等待的 §七纪律由此有了 API 面的机制补偿。
- **失败恢复**：见设计 §七 FMEA（账本＝权威状态，树/会话/凭据可再生；转移幂等；失败必响；有界自动恢复）。

## 修订

- v2（2026-10-23）：全量委托 L1 增补（§四合并约定被「合并职责上移」取代——子会话不再自己合并）。
