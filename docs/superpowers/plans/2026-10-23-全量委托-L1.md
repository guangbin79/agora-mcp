# 全量委托 L1 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地设计 v1.2.1 的 L1 层——agora 建树＋verify 两段制＋链式恢复性重派＋发射加固，全走现有 `opencode run` 路径。

**Architecture:** 机械层改造集中在 task-create.sh（建树）/dispatch.sh（加固）/post.sh（verify 两段）/merge.sh（新）/poll.sh（补档），账本为唯一权威状态；零新依赖、零守护进程。

**Tech Stack:** bash＋python3 stdlib（既有约束）；测试＝tests/smoke-test.sh 追加断言小节。

**Spec:** `docs/全量委托设计-v1.md`（v1.2.1）——计划从规格取值，执行者须同时读规格 §四-§七。

## Global Constraints

- 零新依赖：bash＋git＋python3 stdlib only（README「Dependencies」）
- 规格只追加：既有参数语义不改，新参数/新事件走修订记录（规格 §头部）
- 机械层 git 写边界：仅 attach evidence ref＋agora 自建树生命周期（add/remove/ff merge/**reset**）；不碰用户工作区（设计 §五；v1.29 修订须含 reset）
- 注入防御：外部值一律 env 传数据＋单引号 bash -c，体内零插值（规格 §4.7）
- 统一 fail JSON：`{"code":"...","message":"..."}` 走 stderr（dispatch.sh fail() 先例）
- 测试命令：`bash tests/smoke-test.sh`（先红后绿；全套 0 失败为准）
- `merged` 落账前置＝merge.sh 已在**合并目标**真跑集成 verify（**顺序契约**：post.sh 不跑 verify，但机械校验 `--commit == --branch 指定的合并目标分支当前 HEAD`，防绕过）
- 合并目标二分（设计 v1.2.1）：同仓链（上游 dispatcher 任务主仓归一==本任务主仓）→ 上游 wt 分支；跨仓链/无上游 → 目标仓默认分支

## Review Focus

1. 任务标题含 `$(...)`/反引号 → 不得被 shell 求值 → Task 1 注入断言
2. 重试/重派路径重复建树或重复 spawn → idem＋wt_dir 锚点幂等 → Task 2/4/7 断言
3. 假 runtime 秒死 → diagnosed 落账＋MCP 失败 JSON，禁静默 → Task 4 断言
4. 集成 verify FAIL 后主支残留半合并 → `reset --hard` 零痕迹＋blocked/reopened 落账 → Task 6 断言
5. wt 任务被在场优先降级 notified（树凭据不在场会话侧）→ wt 任务必须 spawned → Task 4 断言
