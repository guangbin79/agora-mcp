## 0. 实证 API 契约（2026-10-23 本机 opencode v2.1.2 /openapi.json 钉死）

- `GET /api/info` → 200（health 探针）。
- `POST /api/session` body `{"title","location":{"directory":"<abs>"}}` → `{"data":{"id":"ses_*",...}}`。
- `GET /api/session/active` → `{"data":{"ses_*":{"type":"running"},...}}`。
- `GET /api/session/{sid}` → `{"data":Session.Info}`；`outcome: succeeded|failed|interrupted`（终态）、`time.idle`（本轮跑完即出现）、`location.directory`（目录绑定）。
- `POST /api/session/{sid}/prompt` body `{"text","delivery":"queue"}` → 即投即跑立即返回。
- 响应一律 `{"data":…}` 包一层；消息列新者在前；assistant 文本在 `content[]{type:"text"}`。

## 1. 架构落点

`scripts/runtime/opencode.sh` 单适配器，子命令＝契约：

| 子命令 | API 序列 | 输出/退出码 |
|---|---|---|
| `health` | GET /api/info | rc0=API 可达 |
| `create <dir>` | POST /api/session（title=agora，location.directory=realpath） | stdout=sid；rc≠0=失败 |
| `inject <sid> <text>` | POST prompt delivery:"queue" | rc0/1（即投即跑，快速返回） |
| `alive <dir>` | GET /api/session/active → 逐 sid GET session 比 location.directory | rc0=该目录有活会话 |
| `status <sid>` | GET /api/session/{sid} | stdout=running∥idle∥dead（outcome/time.idle 归一） |

契约映射说明：任务页「spawn(POST /api/session→prompt→捕获 sid)」由 **create+inject 组合**实现——dispatch.sh 两段调用（见 D1），适配器不设一次性 spawn 子命令（无调用方，不做死代码）。

## 2. 决策记录（开放问题自带默认值）

- **D1 落账序两段化**：API 模式＝create（惰性，无 prompt）→ dispatched(session:<sid>) 落账 → inject(boot) → status 轮询。保 L1「LEDGER_FAILED → 零工作」不变量（一次性 spawn 先投 prompt 会在落账失败时留孤儿工作会话）。create 失败/health 失败发生在落账前 → 直接回落 run，账本与纯 run 完全一致。
- **D2 账本面/机械面对称**：API 模式同 run 维护 `raw/dispatches/<DID>.log`（API 生命周期行 SESSION:<try>=<sid>/ALIVE:<try>=<state>）与 `.live` 标记——poll ②d 孤儿判据「run log 缺失」与配额 .live 计数在 API 模式不破。
- **D3 回落矩阵**：①health/create 失败（未落账）→ run 全路径，**零落账残留**（smoke 断言钉死：账本仅一条无 session: 的 dispatched、无额外派生事件）；②落账后 inject/status 失败 → diagnosed＋重试一次 → 仍败 → run spawn_attempt 兜底（不重发 dispatched，沿现有重试语义；session: 指向死 sid 为已知极限，diagnosed 已响）。
- **D4 注入幂等**：`$AGORA_HOME/.git/inject-tickets/<sid>` 标记（沿 merge-tickets 先例，host-local、不入账本）；已注入再 ack → 跳过 inject，derived=inject_dedup。
- **D5 跨机限定**：inject 前置 wt_host 判则——任务页 wt_host 存在且≠hostname → 不注入；无 wt_host（非 wt 任务）保守回落 spawn 重派（sid 无 host 归属信息，宁慢勿错）。
- **D6 总开关**：`api_enabled = [ "${AGORA_RUNTIME_API:-1}" != "0" ] && [ "$RUNTIME" = "opencode" ]`——默认开；AGORA_RUNTIME≠opencode（stub/替代 runtime）时 API 面整体旁路，既有 smoke 路径零扰动。
- **D7 验证窗语义（轮询 idle）**：AGORA_VERIFY_WIN（默认 10s）内 1s 粒度 status：dead（outcome=failed/interrupted 或 404）→ 秒死；idle（outcome=succeeded ∨ time.idle 出现）→ 过；窗口尽仍 running → 过（与 run「窗口尽仍活=过」同口径）。秒死 → diagnosed＋重试一次（与 run 相同阶梯）。
- **D8 真服务冒烟（T7）**：真 opencode API 全链 spawn→plan→ack 注入→done；AGORA_HOME 隔离沙箱优先，子会话 MCP 落账无法隔离则真实广场一次性自检任务（verify:true，done 即止），结论记回本文件 §6。

## 3. 任务分解（TDD，先红后绿；stub 假 opencode CLI 进 PATH 全离线可测）

stub（tests 内联生成）：假 `opencode` bash 脚本实现 `api`（按 opencode 响应形状 `{"data":…}` 假实现 info/session create/active/get/prompt 五路，行为由 `$FAKE_CTRL` 文件控制 none|health_fail|create_fail|inject_fail|status_dead）＋`run`（rc0）＋`--version`。**stub 只钉契约字段**（data.id/outcome/time.idle/location.directory/delivery），不复制其余 schema——防形状漂移（Review Focus ③）。

- **T1 适配器**＋S1 批：S1a health 通/断；S1b create 出 `ses_` sid（假 data.id）；S1c inject rc0/断电 rc1（假记录 delivery:"queue"）；S1d alive 目录命中/不命中。
- **T2 dispatch API 通道**＋S2 批：S2a API 派生 mode=spawned 且输出含 session 字段，账本 dispatched 行含 `session:ses_*`；S2b health_fail → 回落 run：账本恰一条 dispatched 且**无 session:**、无额外派生事件（零残留）；S2c wt 任务 API 派生凭据预写不变（`.omo/agora-delegation/<task>.md`）；S2d create 成功 inject 恒败 → diagnosed＋run 兜底（降级可观测）。
  - dispatch.sh 改点：预检段 health 替代 `--version`（仅 API 模式）；spawn 段前插 API 分支（create→落账带 --session→inject→status 轮询→.live/日志对称维护）；落账 PARGS 条件追加 `--session "$SID"`。
  - post.sh 改点：`--session` 参数＋字段校验（|/换行环）＋行渲染 ` | session:$SESSION`＋IDEM_INPUT 纳入。
- **T3 ack→注入**＋S3 批：S3a ack 且任务最新 dispatched 带 session: → 假 opencode 收到 inject（ack 已落账，继续）；S3b inject 失败 → ack 仍 rc0，derived 含 inject_failed（best-effort 不阻塞）；S3c 同 sid 二次 ack → 假 inject 计数不增（幂等），derived=inject_dedup；S3d 开关关/无 session: → 零 inject。
  - post.sh 改点：落账 commit 后（flock 内）inject 段：事件=ack ∧ 任务最新 dispatched 带 session: ∧ api_enabled → `timeout` 包裹 inject → 成功落 inject-tickets 标记；失败/跳过仅 derived 注记。
- **T4 poll done-unmerged 注入式续跑**＋S4 批：S4a 上游 dispatched 带 session:（本机）→ 假 inject 收到恢复性续跑 prompt，report.redispatched 含 mode:injected，上游无新 dispatched 事件；S4b inject 失败 → 回落既有 dispatch.sh 重派（新 dispatched）；S4c 上游无 session: → 既有行为不变；S4d 上游页 wt_host≠本机 → 不注入（跨机判则）。
  - poll.sh 改点：scan_tasks dispatched 元组扩 session 捕获（修正既有解包点）；②c 重派前插注入分支。
- **T5 在场 API 化**＋S5 批：S5a 非 wt＋alive(rc0) → mode=notified（sessions.map 不需要）；S5b alive(rc1)＋sessions.map 无 → 正常 spawn；S5c wt＋alive(rc0) → 仍无条件 spawn（既有豁免保住）；S5d 开关关 → sessions.map 旧路径仍工作。
  - dispatch.sh 改点：在场段 alive 优先（api_enabled 才探）、sessions.map 降回退；wt 无条件 spawn 守卫不动。
- **T6 规格与文档**：接口规格 v1.33（§4.7 通道双轨/--session 字段/验证窗 idle 轮询/回落零残留；ack 注入语义与幂等凭据；修订记录）；跨仓委托协议补注入式续跑语义（v2）；全量委托设计题头 v1.3（L2 落地）＋§三补实现注记；README 工具描述同步；VERSION v1.33。无新 smoke 断言（文档批，靠 T7 全绿回归护航）。
