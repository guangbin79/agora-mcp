# 全量委托与链式 worktree 派发 —— 设计 v1.1

> v1.1（2026-10-22）：经双模型对抗评审（interrogate：kimi k3 ＋ glm-5.3）修订——5 条 blocker
> 全部内嵌修复；采纳 ponytail 砍单：裸 git 建树唯一路径、服务 API 适配层分层到 L2。
> 评审原文见会话记录；修复对应关系见 §九。

## 一、意图

主会话退化为**纯编排者**：本机所有代码开发（含当前仓、含 Trivial 级）一律经 agora 委托链
执行——agora 建专用 worktree，受托子会话在树内开发，dispatcher 逐级合并闭环。派发链的
稳定性在**零守护进程原则**下达到「失败必须响」：任何派生失败秒级可见、可恢复、可审计。

## 二、目标 / 非目标 / 反目标

- **目标**：①全量委托闸（机械强制）②agora 建树＋生命周期 ③链式闭环 a→b→c（合并自底向上）
  ④发射加固与恢复（账本为权威状态）
- **非目标**：跨机 worktree（dispatch 本机限定不变）；其他 harness 适配器实现（L2 只留
  契约文档）；shell 写拦截面（单机信任模型，威胁模型文档明示「防误不防绕」）；通知桥重启；
  读操作拦截
- **反目标**：主会话直写码成为常态路径；force push／merge commit；**任何静默失败**；
  verify 门背书未集成状态

## 三、分层交付

- **L1（本设计实施范围，全走 `opencode run` 路径）**：闸、建树、链式、发射加固、
  watchdog/GC 补档。run 在 opencode V2 架构下本就是共享 service 的客户端——「基于服务
  调度」L1 已成立。无新增 spike。
- **L2（spike 验证后另行实施）**：`scripts/runtime/` 服务 API 适配层（spawn/alive/health/
  worktree 四契约），spike 四条：①prompt POST 后客户端断开服务端继续执行 ②服务重启后
  对旧 session 重发 prompt 带上下文续跑 ③`opencode api` 非交互鉴权/自动拉起 ④API 建会话
  是否挂 MCP（v1.23 声称已修复但仅实测注入路径）。深度/配额/在场账本化（§六）在 L1 完成，
  L2 只换通道不换口径。

## 四、全量委托闸（宿主 dotfiles 插件；agora 上游保持无插件）

- **拦截面**：会话 edit/write 目标位于**本机任意 git 仓**即拦（含会话自己 cwd 仓——现插件
  L128 树内放行**反转**；L132 同主仓 worktree 无条件放行**删除**）。未注册仓拦截时引导先建
  实体页。Trivial 豁免取消（operator 定案；成本：typo 级改动也走全链，分钟级开销）。
- **放行**：①目标落在**凭据核验通过**的委托树内（见下）②非 git 目录 ③`/tmp/opencode/`
  scratch ④`AGORA_DELEGATION_OFF=1`。
- **`~/agora` hard-block**：广场只能经 MCP 工具写，edit/write 直写账本一律拦（原豁免反转为
  硬闸，pre-commit 钩子仍兜底）。
- **凭据机制**（keyed by task id，兼容 run 模式不知子会话 ses id）：dispatch 建树后预写
  `<wt_dir>/.omo/agora-delegation/gt-xxxx.md`（内容：gt-id＋树 realpath＋派发时间）；
  dispatcher 侧沿用现行指引写主仓 `.omo/` 同名文件。闸逻辑：扫描会话树根
  `.omo/agora-delegation/gt-*.md`，目标 realpath ∈ 记录树路径 → **交叉核验**该任务页存在
  且其 `wt_dir` 归一后与记录树一致 → 放行。**回退分支**（向后兼容）：非 wt 任务（本机旧式
  委托/跨机任务，任务页无 `wt_dir`）凭据按 `project_dir` 匹配。删除「任意真 gt-id 即永久
  放行」的 `passed` 会话级缓存，改 **per-(sessionID, repoRoot)** 缓存。
- 合并/评审期 dispatcher 动树：主仓侧凭据命中记录树路径，天然放行（无需豁免）。

## 五、worktree 由 agora 建（机械层；v1.29 修订）

- `task-create.sh`：frontmatter 增可选 `wt: true`（仅对含 verify 的任务有意义，纯编排任务
  不建树）。流程：分配 id →（flock **外**）`git -C 主仓 worktree add ../<REPO>__wt-gt-xxxx__
  <MMDDHHMM> -b wt/gt-xxxx` →（锁内）落任务页。任一步失败整体 fail；树孤儿由 doctor GC
  报告。**裸 git 唯一路径**（`POST /api/worktree` 归 L2）。
- **project_dir 保持主仓语义不变**（名册匹配/verify 回填/跨机语义零改动，回填前先经
  `agora_lib.main_repo_of` 归一——修评审 M2 断裂）；新字段 `wt_dir` 承载实际工作区（幂等
  锚点：重派/dispatch 预检树缺失 → 按锚点重建或 post blocked）。
- `task_create` 增可选 `idem` 参数（post 已有先例），修重试泄漏树。
- **环境完备**：新鲜树缺 node_modules/venv 等 → BOOT 模板强制「装环境→验收」；项目页可选
  `setup:` 命令，dispatch 在建好的树内先跑。
- v1.29 修订记录：机械层对项目仓的 git 写边界从「零」扩为「attach evidence ref ＋ agora
  自建树生命周期（add/remove/ff merge）」；其余（用户工作区、分支）仍禁。
- **跨机**：`wt: true` 任务 host 限定（任务页记 hostname）；他机 mention 拾取跳过并报告——
  跨机任务不建树。

## 六、链式闭环与 verify 两段制

- 深度保险丝：默认 `AGORA_MAX_DEPTH=3`（现状 2 掐死 a→b→c）；深度改**从账本推导**
  （dispatched 事件链沿 dispatcher 追溯跳数），run 模式 env 注入保留为兼容。配额同口径
  账本化（活跃=dispatched 集 ∩ 无终态事件）。`dispatched` 事件增记 `session:` id（L2 重发
  prompt 续跑的登记面）。
- **合并职责上移**（跨仓委托协议 §四 → v2）：子会话不合并、done 即止（树上 commit＋自验）；
  dispatcher 收 done → 在合并目标执行 **ff-only** 合并（每跳=上游 dispatcher 的 wt_dir；
  终端=目标仓默认分支，落地动作写明）→ 机械层在**合并后目录真跑任务页 verify** → 落
  `merged` 事件（附 commit）→ 清树。
- **verify 两段**：done 的 verify 在 `wt_dir`（v1.31「实际工作区」口径）；`merged` 的 verify
  在 `project_dir`（集成状态——修「verify 背书未集成状态」blocker）。`merged` 不做提交祖先
  核对（rebase 重写提交不可验），集成 verify 即正确性门。
- **non-ff/冲突**：dispatcher 对任务 post `blocked`（记冲突详情）→ `reopened` → 重派原树
  续跑（rebase 后重走 verify）。
- **合并执行机制**：新增机械脚本 `merge.sh`（ff-only 合并＋集成 verify＋`merged` 落账＋清树
  一体；调用方=合并执行者——恢复性重派的 dispatcher 或 watchdog）。post.sh **不**自动合并。
- **深度推导精确规则**：`dispatched` 事件增记 `dispatcher_task:`（派发时会话正在 claim 的
  任务 id；无任务上下文=空）；深度=沿 dispatcher_task 链计数，无 env 时（L2/API 模式）账本
  为唯一来源，有 env 时（L1 run 模式）env 为权威、账本推导作上限对账（冲突取更大值）。
- **终端合并细节**：目标分支=本地符号 ref 解析（HEAD symref/init.defaultBranch），无远端或
  未配 push 不自动 push（push 归人/宿主流程）；评审时序——子会话 done 前已完成宿主评审
  循环（协议 §三），`merged` 只做集成不重复评审；回滚=git revert ＋ `reopened`。
- **wt 任务跳过在场优先**：`wt: true` 任务无条件 spawn（被通知的在 场会话没有树凭据，
  notified 模式对 wt 任务 100% 卡死）。
- **`~/agora` hard-block 范围**：仅账本与派生面（`log/ board/ wiki/ inbox/ raw/ sessions.map
  .git/hooks 外的派生物`）；agora 仓自身的 scripts/docs 代码走正常全量委托（wt 任务照建树）。
- **链式中间跳驱动模型（OPEN，待 operator 定案）**：run 模式子会话一发即退，b 派 c 后无法
  原地等 c 的 done——三选一：(i) poll 机械自动合并＋恢复性重派（全自动，c 的 diff 无人评
  审即并入）(ii) poll 恢复性重派 b，b 评审 diff 后亲自跑 merge.sh（推荐，保留评审主动权）
  (iii) L1 链式中间跳不做——b 需要改 c 时 post blocked 上抛，由 a（交互会话）扁平编排 c，
  链式协议完整版推 L2。
- watchdog：parent/deps 链上有 in-progress 下级 → 阈值 ×4（消链上等待假阳性）；新增
  「done 超 N min 未 merged → diagnosed @dispatcher」档（消 done≠merged 盲区）。
- BOOT 模板更新：链式协议（等待下级时常发 progress；需第三仓改动照常下钻，受深度/配额
  约束；不自己合并，done 即止；若为恢复性重派，先 `agora_history` 自查进度再续）。
- 落账顺序**补偿化**：dispatched（含 run log 占位）→ spawn → 验证窗（≤10s；秒死 → 日志尾
  落 `diagnosed`，MCP 同步返回失败 JSON）→ 有界重试 1 次。
- GC：poll.sh 家务仅删「任务终态 ＋ 树 clean」的 agora 树（`__wt-gt-` 前缀）；dirty 树只
  报告不删（防 WIP 数据丢失）；清树推迟到终态＋宽限期（reopened 返工与审计重放可用）。

## 七、失败恢复机制（FMEA）

**统一原则**：
1. **账本＝权威状态，树/会话/凭据＝可再生现场**——现场任何丢失都可从账本＋git 分支重建；
2. **转移幂等**：dispatch（idem＋wt 锚点）、merge.sh（检测已合并则补账）、GC（终态＋宽限）；
3. **失败必响**：任何失败路径都有落账事件（diagnosed/blocked/verify_failed），无静默；
4. **有界自动恢复**：同一任务自动重派上限 **3 次**（账本统计 dispatched＋diagnosed 计数），
   超限 `escalated` @operator 交人——恢复机制本身要有保险丝，防无限循环/成本失控；
5. **原子性**：task-create（树＋页同成败）、merge（合并＋verify＋落账要么全成、要么零痕迹
   或可补账）；
6. **分级响应**：秒级＝MCP 同步失败返回 → 分钟级＝cron poll 梯队（diagnosed/重派/自动
   合并，≤5min）→ 人工＝escalated。

**恢复矩阵**（检测者全部为零守护设施：MCP 返回/poll 梯队/doctor）：

| # | 故障 | 检测 | 恢复动作 |
|---|------|------|----------|
| A1 | 建树失败（磁盘/撞名/锁） | task-create 同步 fail | 零落账；idem 重试 |
| A2 | 预检失败（runtime 不在/目录缺） | dispatch 同步 fail JSON | 调用方立刻可见 |
| B1 | 子会话秒死 | 验证窗（≤10s） | 日志尾落 diagnosed＋重试 1 |
| B3 | dispatched 落账后 spawn 前崩溃 | poll：dispatched 事件存在但无 run log/.live | 孤儿 dispatched 档→diagnosed→重派 |
| B4 | 树成页未写（task-create 崩溃窗） | doctor：`__wt-gt-` 树无任务页 | GC 报告（不自动删） |
| C1 | 子会话崩溃/OOM/API 断流 | claimed 无心跳 40min（watchdog） | **恢复性重派**：不重建树（锚点复用），续跑 BOOT＝先 `agora_history` 自查→`git status/log` 查半成品→接着做；凭据随重派**幂等重写** |
| C2 | 子会话卡死 | .live 滞留（stale-live 档） | diagnosed @派单方→kill＋重派 |
| C3 | 崩溃时留 dirty WIP | 重派后 `git status` | 子会话接手现场；GC 对 dirty 树只报告 |
| C5 | **机器重启**（进程全灭/.live 残留） | 重启后 cron 自启→stale-live＋watchdog 双档 | 同 C1/C2；crontab 持久即恢复入口 |
| D2 | c 的树被误删（分支仍在） | merge.sh/重派预检树缺失 | 按 `wt_dir` 锚点同分支重建 checkout——**提交不丢，仅丢未提交 WIP** |
| D3 | 重派后再次崩溃 | 账本重派计数 | ≤3 次继续重派；超限 escalated，停止自动恢复 |
| D4 | 链上任一环 cancelled | done 自动 @ 上行 | 上游收 mention 自行决策（blocked/取消/改派） |
| E1 | 合并 non-ff/冲突 | merge.sh ff-only 失败 | blocked（记冲突详情）→reopened→重派原树 rebase 后重走 verify |
| E2 | 集成 verify FAIL（合并后语义破坏） | merge.sh 在合并后目录真跑 verify | **原子回滚**：`git reset --hard <pre-merge>`（未 push，安全）→主支零痕迹→blocked 落账（附 verify 输出）→reopened |
| E3 | merge.sh 崩溃于 verify 后落账前 | 主支已含 done 提交但无 merged 事件 | 幂等重跑：检测已合并→只补落账 |
| E4 | 清树失败（占用） | GC 下轮 | 终态＋宽限＋clean 判据重试 |
| F1 | 账本写失败（flock 超时） | post.sh fail JSON | 调用方重试（现有 idem 幂等窗） |
| F2 | 账本仓损坏 | doctor 自检 | backup.sh bundle 恢复（现状） |
| F3 | opencode 服务整体不可用 | 派发预检拦前；在跑会话→C1 路径 | 服务恢复后 poll 梯队自动重派 |
| G1 | 凭据文件丢失（树重建/GC） | 闸拦截子会话 | 每次 dispatch/重派都幂等重写凭据（子侧） |
| G2 | 凭据伪造/误写 | 闸交叉核验拒 | 审计走 `agora_history` |

**与 OPEN ①（链式驱动模型）的关系**：恢复性重派＋poll 梯队是三个选项的共同地基；(ii)
只是把恢复原语同时用于正常流（b 等 c＝主动退出＋按需重派），故恢复机制与 (ii) 协同最佳、
实现成本最低（零新增机制）。

## 十、裁量记录（设计者 call，请 operator 复核）

1. 凭据 keyed by task id（非 session id），dispatch 预写子侧＋指引写主仓侧。
2. `project_dir` 保持主仓语义，`wt_dir` 新字段承载工作区；verify 两段制。
3. 树命名 `../<REPO>__wt-gt-xxxx__<MMDDHHMM>`、分支 `wt/gt-xxxx`（agora 自有命名域）。
4. `merged` 不验祖先；集成 verify 为正确性门。
5. 验证窗 ≤10s、重试 1 次。
6. L1/L2 切分与 spike 清单（§三）。
7. Trivial 豁免取消按 operator 定案保留（成本已注明）。
8. `~/agora` hard-block（原豁免反转，范围=账本面，见 §四/§六）。
9. 闸跨核验回退分支：非 wt 任务按 `project_dir` 匹配（向后兼容本机旧式与跨机委托）。
10. `merge.sh` 独立机械脚本承载合并闭环；post.sh 不自动合并。
11. 深度推导：`dispatcher_task` 链计数；L1 env 权威＋账本上限对账。
12. 终端合并不自动 push；评审在 done 前完成，merged 仅集成。
13. wt 任务跳过在场优先（无条件 spawn）。
14. 自动重派上限 3 次（超限 escalated）；重派计数走账本（dispatched＋diagnosed 统计）。
15. merge.sh 原子性：集成 verify FAIL → `reset --hard` 回滚主支（未 push 前提）；崩溃后
    幂等补账。
16. 树误删恢复＝同分支重建 checkout（提交不丢，接受丢未提交 WIP）。
17. 凭据随每次 dispatch/重派幂等重写。

**留给实施者**：验证窗精确值、GC 宽限期数值、watchdog ×4 豁免的实现位置（derive 层标记 vs
poll 逻辑）、BOOT 措辞、smoke 用例完整枚举、`setup:` 执行时机细节、`.omo` 凭据文件格式字段、
重派计数的统计口径实现（事件扫描 vs 任务页计数器）。
